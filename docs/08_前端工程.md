## 原理讲解

### 1. 项目技术栈与构建配置

本项目前端采用 Vue 3 Composition API + Vite 构建，配合 Element Plus 组件库和 ECharts 可视化库。

```
前端技术栈架构
┌─────────────────────────────────────────────────┐
│                  Vite Dev Server                 │
├─────────────────────────────────────────────────┤
│   Vue 3 (Composition API + <script setup>)      │
├───────────┬───────────┬───────────┬─────────────┤
│ Element   │   Pinia   │ Vue Router│   ECharts   │
│  Plus     │  (Store)  │   (路由)  │   (图表)    │
├───────────┴───────────┴───────────┴─────────────┤
│              Axios (HTTP 客户端)                  │
└─────────────────────────────────────────────────┘
```

Vite 配置中使用 `unplugin-auto-import` 减少手动 import，通过 `build.rollupOptions.output.manualChunks` 将 element-plus、echarts、vue 拆分为独立 chunk，优化首屏加载。

### 2. 项目目录结构

```
frontend/src/
├── api/              # API 请求封装
│   └── client.js     # Axios 实例、拦截器、统一错误处理
├── stores/           # Pinia 状态管理
│   └── session.js    # 会话认证状态（持久化）
├── router/           # 路由配置
│   └── index.js      # 路由表、懒加载、导航守卫
├── layouts/          # 布局组件
│   ├── ClientLayout.vue    # 用户端（可折叠侧边栏）
│   └── AdminLayout.vue     # 管理端布局
├── views/            # 页面组件
│   ├── MockInterview.vue   # 串行问答面试页
│   └── Reports.vue         # ECharts 雷达图报告页
└── components/       # 通用业务组件
```

### 3. Axios 拦截器工作流

```
请求发起 ──> 请求拦截器 ──> 后端服务 ──> 响应拦截器 ──> 组件接收
               │                            │
               ├─ 从 store 读取 token       ├─ 2xx: 返回 data
               ├─ 注入 Authorization        ├─ 401: 清除会话 → 跳转登录
               └─ 设置 Content-Type         ├─ 403: 提示无权限
                                            └─ 其他: ElMessage.error 弹出
```

关键设计：请求拦截器从 Pinia session store 读取 token 注入 `Authorization: Bearer <token>`；响应拦截器统一捕获错误状态码，401 时调用 `session.logout()` 并 `router.push('/login')`，其他错误提取 `response.data.detail` 通过 Element Plus 的 ElMessage 展示。

### 4. Pinia 持久化会话

```javascript
// 核心原理：pinia-plugin-persistedstate
defineStore('session', {
  state: () => ({ token: null, user: null, roles: [] }),
  persist: {
    key: 'ai-interview-session',
    storage: localStorage,
    paths: ['token', 'user', 'roles']
  }
})
```

页面刷新时 Pinia 自动从 localStorage 反序列化状态，Axios 拦截器即可立即获取有效 token，无需用户重新登录。

### 5. 路由懒加载与权限守卫

```
用户访问路由
    │
    ▼
beforeEach 守卫
    │
    ├─ meta.requiresAuth === true ?
    │       │
    │       ├─ 未登录 → redirect('/login')
    │       │
    │       └─ 已登录 → 检查 meta.roles
    │               │
    │               ├─ 角色匹配 → 放行
    │               └─ 角色不匹配 → redirect('/403')
    │
    └─ 无需认证 → 放行
```

路由使用 `() => import('./views/Xxx.vue')` 实现按需加载，减少初始 bundle 体积。

### 6. 双布局系统

ClientLayout 提供可折叠侧边栏（el-menu + collapse 状态），适合用户端操作密集场景；AdminLayout 采用固定宽侧边栏 + 面包屑导航，适合管理后台。两套布局通过路由嵌套 children 隔离，互不干扰。

### 7. 串行问答面试 UI

面试采用"逐题作答"模式：展示当前题目 → 用户输入 → 提交 → 下一题。配合 `setInterval` 计时器显示答题耗时，`computed` 实时统计字数，`watch` + 防抖将草稿写入 localStorage，防止意外关闭丢失内容。

## 实验步骤

### 实验一：Axios 拦截器验证

1. 启动前端 `npm run dev`，打开浏览器 DevTools Network 面板
2. 未登录状态访问 `/mock-interview`，确认自动跳转到 `/login`
3. 登录后观察请求 header 中 `Authorization: Bearer xxx` 是否存在
4. 在 Application → localStorage 中手动删除 token，刷新页面观察行为
5. 使用 DevTools 模拟后端返回 401，确认前端自动跳转登录页

### 实验二：路由权限与懒加载

1. 以普通用户登录，在地址栏手动输入 `/admin/dashboard`
2. 确认被重定向到 403 页面或首页
3. 以管理员登录，确认可正常访问管理页面
4. 打开 Network 面板，观察路由切换时 JS chunk 按需加载

### 实验三：面试 UI 草稿保存

1. 进入模拟面试页面，开始答题
2. 输入部分内容后直接关闭浏览器标签页
3. 重新打开同一面试页面，确认草稿自动恢复
4. 验证计时器从 0 重新开始（计时不持久化）
5. 提交回答后确认 localStorage 中对应草稿被清除

### 实验四：ECharts 雷达图渲染

1. 完成一场面试并生成报告
2. 进入报告页面，确认雷达图正确展示各维度分数
3. 缩放浏览器窗口，确认图表自适应 resize
4. 在 DevTools Console 中修改数据，调用 `chart.setOption()` 验证响应式

## 练习任务

### 任务一：实现暗色主题切换（基础）

在 ClientLayout 顶部栏添加主题切换按钮，利用 Element Plus 暗色模式 CSS 变量（`html.dark` class），将用户偏好持久化到 localStorage，刷新后保持选择。

### 任务二：添加请求重试与取消机制（进阶）

在 Axios 拦截器中实现：网络错误自动重试（最多 3 次，指数退避）；页面切换时通过 AbortController 取消未完成请求；对 5xx 重试，4xx 不重试。

### 任务三：面试回答字数限制与进度提示（进阶）

在 MockInterview.vue 中添加 2000 字上限，超出时禁用提交按钮并显示红色警告，textarea 下方用 el-progress 展示已用字数百分比。

### 任务四：封装通用雷达图组件（高级）

将 Reports.vue 中 ECharts 逻辑抽取为 `<RadarChart :data="scores" :indicators="dims" />`，支持：自适应容器尺寸、v-loading 加载态、空数据占位图、主题色跟随系统。

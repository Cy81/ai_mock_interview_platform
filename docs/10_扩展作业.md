## 学习目标

| 序号 | 目标 | 层级 | 验证方式 |
|------|------|------|----------|
| 1 | 能独立扩展 RAG 知识库并验证对面试题目的影响 | 应用 | 新增岗位方向后面试题目发生变化 |

## 作业一：新增岗位方向与 RAG 文档（基础）

### 背景说明

当前系统支持若干岗位方向（如后端开发、前端开发、数据分析等），每个方向关联特定的 RAG 文档（题库和知识库）。本作业要求新增一个全新的岗位方向，并验证系统能基于新文档生成针对性的面试题目。

这是理解 RAG 驱动面试系统的最直接方式：改变知识源，观察输出变化。

### 技术要点

```
新增岗位方向的数据流
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 准备 RAG 文档 │────>│ 入库并向量化  │────>│ 创建面试验证  │
│ (题库+知识库) │     │ (切分+嵌入)  │     │ (检索+出题)  │
└──────────────┘     └──────────────┘     └──────────────┘
```

- RAG 文档格式：遵循现有 `question_bank` 和 `knowledge_base` 的结构
- 向量化流程：通过 API 或 Celery 任务完成文档切分和 Embedding 入库
- 检索验证：新岗位面试时，检索结果应命中新入库的文档片段
- 岗位配置：在岗位方向表中注册新方向，关联 metadata 过滤条件

### 参考实现思路

1. 选择一个新岗位方向（如"DevOps 工程师"或"产品经理"）
2. 准备 5-10 道该方向的面试题目文档（question_bank 类型）
3. 准备 3-5 篇该方向的知识库文档（knowledge_base 类型）
4. 通过 RAG 管理接口入库，确认切分和索引完成
5. 创建该方向的面试会话，观察生成的题目是否来自新文档
6. 对比：同一用户简历在不同岗位方向下获得的题目差异

### 验收标准

| 项目 | 要求 |
|------|------|
| 文档入库 | 新方向的 question_bank 和 knowledge_base 文档成功入库并可检索 |
| 题目生成 | 新方向面试生成的题目与入库文档内容相关，而非通用题目 |
| 隔离性 | 其他岗位方向的面试不会检索到新方向的文档 |
| 可回归 | 提供测试用例验证新方向的检索召回率 |

## 作业二：多轮追问交互（进阶）

### 背景说明

当前面试采用"一问一答"串行模式，每道题只有一次回答机会。真实面试中，面试官会根据候选人的回答进行追问以深入考察。本作业要求实现基于 SSE 流式端点的多轮追问功能：AI 根据用户回答实时生成追问，用户可以继续补充回答。

### 技术要点

```
多轮追问交互时序
┌────────┐          ┌────────┐          ┌────────┐
│  前端  │          │  后端  │          │ AI API │
└───┬────┘          └───┬────┘          └───┬────┘
    │  提交回答          │                   │
    │──────────────────>│                   │
    │                   │  构造追问 Prompt    │
    │                   │──────────────────>│
    │  SSE: 追问流式返回  │  stream response  │
    │<──────────────────│<──────────────────│
    │                   │                   │
    │  提交追问回答       │                   │
    │──────────────────>│                   │
    │                   │  判断是否继续追问   │
    │  SSE: 评价或下一问  │                   │
    │<──────────────────│                   │
```

- SSE 端点设计：`POST /api/interviews/{id}/followup`，返回 `text/event-stream`
- 上下文管理：将原始题目 + 用户回答 + 追问历史拼接为 Prompt 上下文
- 追问轮次控制：设置最大追问次数（建议 2-3 轮），避免无限循环
- 前端流式渲染：使用 `EventSource` 或 `fetch` + `ReadableStream` 逐字展示
- 状态管理：追问过程中禁用"下一题"按钮，追问结束后恢复

### 参考实现思路

1. 后端新增 `/api/interviews/{id}/questions/{qid}/followup` SSE 端点
2. Prompt 模板：包含原题、用户回答、要求 AI 判断是否需要追问
3. AI 返回格式约定：`{"type": "followup", "content": "..."}` 或 `{"type": "satisfied"}`
4. 前端 MockInterview.vue 新增追问消息列表，类似聊天气泡布局
5. 流式接收时逐字追加到当前追问气泡中
6. 追问回答提交后重复流程，直到 AI 返回 satisfied 或达到轮次上限

### 验收标准

| 项目 | 要求 |
|------|------|
| 流式展示 | 追问内容通过 SSE 实时逐字展示，无需等待完整响应 |
| 上下文连贯 | 追问内容与用户前序回答逻辑相关，非随机生成 |
| 轮次控制 | 最多追问 N 轮后自动结束，进入下一题 |
| 错误处理 | SSE 连接断开时前端给出提示，支持重试 |
| 评分整合 | 追问回答纳入最终评分，报告中体现追问环节表现 |

## 作业三：简历对比功能（高级）

### 背景说明

招聘场景中，HR 经常需要对比多位候选人在同一岗位上的匹配度。本作业要求实现"简历对比"功能：选择两份简历和一个目标岗位，系统生成对比分析报告，包含各维度的优劣势对比和综合推荐。

### 技术要点

```
简历对比数据流
┌──────────┐  ┌──────────┐  ┌──────────┐
│ 简历 A   │  │ 简历 B   │  │ 目标岗位  │
└────┬─────┘  └────┬─────┘  └────┬─────┘
     │              │              │
     └──────────────┼──────────────┘
                    ▼
          ┌─────────────────┐
          │  AI 对比分析     │
          │  · 技能匹配度   │
          │  · 经验相关性   │
          │  · 成长潜力     │
          │  · 综合推荐     │
          └────────┬────────┘
                   ▼
          ┌─────────────────┐
          │  对比报告展示    │
          │  · 并排对比表   │
          │  · 雷达图叠加   │
          │  · 推荐结论     │
          └─────────────────┘
```

- 数据模型：新增 `resume_comparisons` 表，关联两份简历和目标岗位
- API 设计：`POST /api/comparisons` 创建对比，`GET /api/comparisons/{id}` 获取结果
- Prompt 工程：将两份简历结构化信息 + 岗位要求组合为对比 Prompt
- 输出结构：JSON 格式包含各维度评分（双方）、优劣势列表、综合推荐
- 前端展示：并排卡片 + ECharts 雷达图叠加（两条数据线）

### 参考实现思路

1. 数据库新增 `resume_comparisons` 表：resume_a_id, resume_b_id, job_direction, result_json
2. 后端服务层：获取两份简历的解析结果，拼接对比 Prompt
3. Prompt 设计要点：要求 AI 从技能覆盖、项目经验、教育背景、成长潜力四个维度打分
4. 返回结构化 JSON，包含 `dimensions: [{name, score_a, score_b, analysis}]`
5. 前端新增 CompareResumes.vue 页面：选择简历 → 选择岗位 → 生成对比
6. 结果页使用 ECharts 雷达图叠加展示，配合表格详细对比

### 验收标准

| 项目 | 要求 |
|------|------|
| 功能完整 | 能选择两份简历和岗位，生成对比报告 |
| 维度评分 | 至少 4 个维度的量化评分，双方均有分数 |
| 可视化 | 雷达图正确叠加两条数据线，图例清晰 |
| 分析质量 | 每个维度有文字分析，结论有理有据 |
| 边界处理 | 同一简历对比自身时给出提示，简历不存在时返回 404 |

## 作业四：A/B 评分机制（挑战）

### 背景说明

AI 评分的质量高度依赖 Prompt 设计。不同的评分 Prompt 可能产生显著不同的结果：有的偏严格，有的偏宽松，有的关注技术深度，有的关注表达能力。本作业要求实现 A/B 评分机制：同一份面试回答使用两套不同的评分 Prompt 分别打分，对比结果差异，为 Prompt 优化提供数据支撑。

### 技术要点

```
A/B 评分架构
┌─────────────────────────────────────────────────┐
│              面试回答 (answers)                   │
└───────────────────────┬─────────────────────────┘
                        │
              ┌─────────┴─────────┐
              ▼                   ▼
    ┌─────────────────┐ ┌─────────────────┐
    │  Prompt A       │ │  Prompt B       │
    │  (当前生产版本)  │ │  (实验候选版本)  │
    └────────┬────────┘ └────────┬────────┘
             │                   │
             ▼                   ▼
    ┌─────────────────┐ ┌─────────────────┐
    │  评分结果 A      │ │  评分结果 B      │
    │  · 总分         │ │  · 总分         │
    │  · 维度分       │ │  · 维度分       │
    │  · 反馈文本     │ │  · 反馈文本     │
    └────────┬────────┘ └────────┬────────┘
             │                   │
             └─────────┬─────────┘
                       ▼
             ┌─────────────────┐
             │  对比分析面板    │
             │  · 分数差异     │
             │  · 一致性指标   │
             │  · Prompt 推荐  │
             └─────────────────┘
```

- Prompt 版本管理：新增 `scoring_prompts` 表，存储多版本评分 Prompt
- A/B 分配策略：可按面试 ID 哈希分配，或对同一面试同时执行两套
- 并行评分：使用 `asyncio.gather` 并行调用两次 AI API，减少等待时间
- 结果存储：`scoring_results` 表关联 interview_id + prompt_version
- 对比指标：总分差异、各维度相关系数、评分一致性百分比
- 管理界面：管理员可查看 A/B 对比统计，决定是否上线新 Prompt

### 参考实现思路

1. 数据库设计：
   - `scoring_prompts`：id, version, name, content, is_active, created_at
   - `scoring_results`：id, interview_id, prompt_id, total_score, dimensions_json, feedback
2. 后端评分服务改造：接受 prompt_id 参数，支持指定 Prompt 版本评分
3. A/B 触发逻辑：面试完成时，若存在实验版 Prompt，则并行执行两套评分
4. 对比 API：`GET /api/admin/ab-scoring/stats` 返回聚合统计
5. 前端管理页面：
   - Prompt 版本列表（CRUD）
   - A/B 实验配置（选择对照组和实验组）
   - 对比结果看板：箱线图展示分数分布差异，表格展示逐题对比
6. 决策支持：当实验组在一致性和区分度上优于对照组时，提示可上线

### 验收标准

| 项目 | 要求 |
|------|------|
| Prompt 管理 | 能创建、编辑、激活/停用评分 Prompt 版本 |
| 并行评分 | 同一面试能被两套 Prompt 同时评分，结果独立存储 |
| 对比展示 | 管理员能查看两套评分的分数差异和一致性指标 |
| 统计分析 | 累计多场面试后能展示聚合统计（均值、标准差、相关系数） |
| 性能影响 | 并行评分不显著增加用户等待时间（相比单次评分增加 < 20%） |
| 数据隔离 | 用户端只展示生产版 Prompt 的评分结果，实验版仅管理员可见 |

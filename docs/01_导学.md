# 01 导学：从求职业务闭环理解企业 AI 应用工程

## 学习目标

| 维度 | 达标标准 |
|------|----------|
| 业务理解 | 能画出"简历→画像→岗位推荐→面试→评分→学习计划"六步闭环 |
| 技术选型 | 能说明每层技术选型的理由（FastAPI vs Django、pgvector vs Milvus 等） |
| 环境搭建 | 能用 `docker compose up` 一键启动全栈，Mock 模式跑通完整流程 |
| 工程意识 | 理解"LLM 只是能力模块"——真正的工程难点在流程可恢复、输出可校验、系统可观测 |

## 一、业务背景与痛点

### 1.1 传统面试准备的问题

- 候选人不知道自己的技能与目标岗位的差距
- 面试题准备缺乏针对性，无法根据简历定制
- 练习后没有结构化反馈，无法量化进步

### 1.2 AI 模拟面试平台的价值主张

```text
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 简历上传 │───>│ 画像提取  │───>│ 岗位推荐  │───>│ 定制出题  │───>│ 回答评分  │───>│ 学习计划  │
└─────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
     │              │               │               │               │               │
  python-magic   AI JSON解析    LangChain Agent   题库RAG检索     知识库RAG辅助    维度雷达图
  多格式解析     结构化输出      Tool Calling      pgvector HNSW   逐题comment     学习路径
```

每一步都有明确的输入/输出契约，AI 失败时有规则兜底，保证用户体验不中断。

## 二、技术栈全景与选型理由

### 2.1 后端

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| FastAPI | 0.110+ | 原生 async、自动 OpenAPI、Depends 依赖注入 |
| SQLAlchemy 2.x | 2.0+ | 类型安全 ORM、支持 pgvector 扩展列 |
| PostgreSQL + pgvector | 16 | HNSW 索引、cosine_distance 原生算子 |
| Alembic | 1.13+ | 版本化迁移、CI/CD 友好 |
| Redis | 7 | Celery Broker + 未来缓存层 |
| Celery | 5.3+ | 异步任务（索引/评分）、重试/幂等/死信 |
| DeepSeek API | — | OpenAI 兼容协议、JSON Mode、流式输出 |
| DashScope Embedding | — | 中文语义向量、批量接口 |
| tenacity | 9+ | 指数退避重试、AI 调用容错 |
| structlog | — | 结构化 JSON 日志、请求链路追踪 |
| Prometheus + Sentry | — | 指标采集 + 异常上报 |

### 2.2 前端

| 技术 | 选型理由 |
|------|----------|
| Vue 3 + Composition API | 响应式 + 逻辑复用 |

| Pinia + persistedstate | 状态管理 + 刷新不丢 |
| ECharts (vue-echarts) | 雷达图/趋势图/柱状图 |
| Axios | 拦截器统一鉴权/错误处理 |

### 2.3 工程化

| 工具 | 用途 |
|------|------|
| Docker Compose | 一键编排 7 个服务 |
| Nginx | 反向代理、gzip、安全头、SSE 透传 |
| Makefile | 开发/测试/部署快捷命令 |
| pytest + respx | 后端单元/集成测试 |

## 四、环境搭建与首次运行

### 4.1 前置条件

- Docker Desktop（Windows/Mac）或 Docker Engine（Linux）
- Node.js 20+（仅本地开发前端时需要）
- Python 3.11+（仅本地开发后端时需要）

### 4.2 一键启动

```bash
# 克隆项目
git clone <repo-url> && cd ai_mock_interview_platform

# 复制环境变量（默认 Mock 模式，无需 API Key）
cp .env.example .env

# 启动全部服务
make up
# 或
docker compose up -d --build
```

启动后访问：
- 前端工作台：http://localhost
- 后端 API 文档：http://localhost:8000/docs
- 健康检查：http://localhost/healthz

### 4.3 默认账号

| 角色 | 邮箱 | 密码 |
|------|------|------|
| 超级管理员 | admin@ai-interview.com | admin123 |
| 普通用户 | 自行注册 | 8位+字母+数字 |

### 4.4 Mock 模式说明

```env
AI_RUNTIME=mock           # AI 调用返回固定 JSON，不消耗 API 额度
EMBEDDING_RUNTIME=mock    # Embedding 返回随机向量，不依赖外部服务
```

Mock 的价值：
1. 学习者零成本跑通全流程
2. CI 测试不依赖外部网络
3. 前端开发不被后端 AI 延迟阻塞

切换到真实模型只需修改 `.env`：
```env
AI_RUNTIME=deepseek
AI_API_KEY=sk-xxx
EMBEDDING_RUNTIME=dashscope
EMBEDDING_API_KEY=sk-xxx
```

## 五、课堂主流程演练

1. **注册账号** → 登录页，填写邮箱/姓名/密码（8位+字母+数字）
2. **上传简历** → 简历解析页，粘贴文本或上传 PDF/DOCX
3. **岗位推荐** → 岗位匹配页，选择简历，点击"生成推荐"
4. **发起面试** → 模拟面试页，选择简历+岗位+题量，创建面试
5. **逐题作答** → 串行 Q&A，每题有计时器和字数统计
6. **完成评分** → 点击"完成并出报告"，跳转到评分报告页
7. **查看报告** → 雷达图 + 维度对比 + 逐题反馈 + 学习计划
8. **管理后台** → 右上角切换，查看用户/岗位/RAG/面试统计

## 六、生产化工程思维

企业项目中，LLM 只是一个能力模块。真正的工程难点在于：

| 维度 | 本项目的做法 |
|------|-------------|
| 流程可恢复 | Interview 状态机（created→generating→in_progress→scoring→completed/failed） |
| 输出可校验 | AI 强制 JSON Mode + Pydantic 解析 + 异常降级 |
| 幂等防抖 | idempotency_key UniqueConstraint |
| 可观测 | structlog JSON + X-Request-ID + Prometheus /metrics + Sentry |
| 安全 | JWT access+refresh、失败锁定、角色分层、资源归属校验 |
| 可测试 | Mock Provider + pytest + respx + SQLite StaticPool |
| 可部署 | Docker Compose + Nginx + Gunicorn + Celery + Alembic |

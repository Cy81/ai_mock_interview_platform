# 生产级上线清单

本文档用于把项目从“本地能跑”推进到“可以生产部署和持续维护”的最低工程基线。

## 1. 必填环境变量

生产环境必须显式设置：

```env
ENVIRONMENT=production
DEBUG=false
LOG_JSON=true
AUTO_CREATE_TABLES=false
DATABASE_URL=postgresql+psycopg://<user>:<password>@postgres:5432/interview
REDIS_URL=redis://redis:6379/0
SECRET_KEY=<至少32位的随机密钥>
CORS_ORIGINS=https://你的域名
DEFAULT_ADMIN_EMAIL=admin@your-domain.com
DEFAULT_ADMIN_PASSWORD=<强密码，不要使用admin123>
```

如果启用真实模型，还必须设置：

```env
AI_RUNTIME=deepseek
DEEPSEEK_API_KEY=<DeepSeek API Key>

EMBEDDING_RUNTIME=dashscope
DASHSCOPE_API_KEY=<DashScope API Key>
```

生产模式会拒绝以下危险配置：

- 默认或过短 `SECRET_KEY`
- SQLite 数据库
- `AUTO_CREATE_TABLES=true`
- `DEBUG=true`
- 默认管理员密码 `admin123`
- `localhost` 或 `*` CORS 来源
- 启用真实 AI/Embedding 但没有配置对应 API Key

## 2. 启动流程

容器启动时后端会执行：

```bash
alembic upgrade head
```

开发/测试环境会继续执行种子数据脚本；生产环境会自动跳过 seed，避免默认数据和默认管理员密码进入线上。

## 3. 健康检查

- `/healthz`：进程存活检查，只返回服务是否还在响应。
- `/readyz`：就绪检查，会真实检查数据库和 Redis。任一依赖失败时返回 `503`。
- `/metrics`：Prometheus 指标，生产环境建议只暴露给内网或监控系统。

## 4. CI 门禁

GitHub Actions 会执行：

```bash
cd backend && python -m pytest
cd frontend && npm run test
cd frontend && npm run build
```

合并到 `main` 前至少保证这些检查通过。

## 5. 部署后验收

```bash
curl -f http://<host>/healthz
curl -f http://<host>/readyz
curl -i http://<host>/api/v1/auth/me
```

其中 `/api/v1/auth/me` 未登录时返回 `401` 属于正常结果，说明 API 代理和后端认证链路可达。

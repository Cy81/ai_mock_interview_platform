## 二、后端分层原则

### 2.1 五层职责

| 层 | 目录 | 职责 | 禁止 |
|----|------|------|------|
| Router | `app/api/v1/` | 参数接收、权限依赖、响应模型声明 | 业务逻辑 |
| Schema | `app/schemas/` | 请求/响应数据结构、校验规则 | DB 操作 |
| Service | `app/services/` | 业务编排、AI/RAG 调用、事务控制 | HTTP 概念 |
| Model | `app/models/` | ORM 映射、关系定义、枚举 | 业务判断 |
| DB | `app/db/` | 连接池、会话管理 | 业务逻辑 |

### 2.2 依赖注入（Depends）

```python
# app/api/deps.py 核心依赖
get_db          → SQLAlchemy Session（请求级生命周期）
get_current_user → JWT 解码 + DB 查询，返回 User 实例
get_current_admin → get_current_user + role in (admin, superadmin)
get_current_superadmin → get_current_user + role == superadmin
limiter         → slowapi Limiter(key_func=get_remote_address)
```

## 三、双端路由隔离

```python
# app/main.py
app.include_router(client_router, prefix="/api/v1")
app.include_router(admin_router, prefix="/api/v1/admin")
```

- **client_router**：resumes / jobs / interviews / reports / rag(search only) / auth
- **admin_router**：system(users) / jobs(CRUD) / rag(CRUD+upload+reindex) / interviews(list+stats)

管理端每个路由都依赖 `get_current_admin`，客户端路由依赖 `get_current_user`。资源归属校验在 Service 层完成（`resume.user_id == user.id`）。

## 四、中间件链

```text
请求进入 → RequestContextMiddleware（注入 X-Request-ID、计时）
        → SlowAPI RateLimiter（登录/注册限流）
        → CORSMiddleware（开发环境 allow_origins=*）
        → FastAPI Router 匹配
        → Depends 依赖解析
        → 路由函数执行
        → 异常处理器（如果抛出）
        → 响应返回（附加 X-Process-Time-Ms）
```

### 代码导读：`app/core/middleware.py`

```python
class RequestContextMiddleware:
    async def __call__(self, request, call_next):
        request_id = request.headers.get("X-Request-ID") or uuid4().hex[:16]
        start = time.perf_counter()
        response = await call_next(request)
        response.headers["X-Request-ID"] = request_id
        response.headers["X-Process-Time-Ms"] = str(int((time.perf_counter() - start) * 1000))
        return response
```

## 五、统一错误体系

### 5.1 异常层级

```text
DomainError (400)
├── NotFoundError (404)
├── ConflictError (409)
└── PermissionDenied (403)
```

### 5.2 统一响应格式

```json
{
  "detail": "简历不存在或无权限访问",
  "code": "NOT_FOUND",
  "request_id": "a1b2c3d4e5f6"
}
```

### 5.3 额外处理器

| 异常类型 | HTTP 状态码 | 处理逻辑 |
|----------|-------------|----------|
| RequestValidationError | 422 | 提取字段名+消息 |
| IntegrityError | 409 | 唯一约束冲突 |
| SQLAlchemyError | 500 | 日志记录，返回通用错误 |
| HTTPException | 原始码 | 透传 |
| Exception | 500 | Sentry 上报 + 通用错误 |

## 六、Lifespan 事件

```python
@asynccontextmanager
async def lifespan(app):
    # 启动时
    if settings.AUTO_CREATE_TABLES:
        init_db()  # 仅开发/测试环境
    if settings.SENTRY_DSN:
        sentry_sdk.init(dsn=settings.SENTRY_DSN)
    yield
    # 关闭时（清理资源）
```

生产环境 `AUTO_CREATE_TABLES=False`，表结构由 Alembic 管理。

## 七、数据流示例：创建面试

```text
POST /api/v1/interviews
  → get_current_user (JWT 校验)
  → InterviewCreate schema 校验 (resume_id, job_code, question_count, idempotency_key)
  → interview_service.create_interview()
      → 幂等检查 (idempotency_key)
      → 校验 resume 归属 + job 存在
      → 状态: GENERATING
      → 题库 RAG 检索 (question_bank)
      → AI Provider 生成结构化题目 (JSON Mode)
      → 写入 InterviewQuestion 子表
      → 状态: IN_PROGRESS
  → 返回 InterviewRead (含 questions)
```
